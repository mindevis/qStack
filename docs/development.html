Разработка

Инструкция по настройке локальной среды разработки для qStack.

Быстрый старт

Bash
# 1. Клонировать репозиторий
git clone https://github.com/mindever/qStack.git
cd qStack

# 2. Запустить инфраструктуру (PostgreSQL, NATS, Observability)
make infra-up

# 3. Инициализировать БД
make db-migrate

# 4. Сгенерировать gRPC код
make proto-gen

# 5. Запустить сервисы
make dev

Docker Compose (Development)

Для локальной разработки используется docker-compose.yml:

docker-compose.yml
services:
  # Infrastructure
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: qstack
      POSTGRES_USER: qstack
      POSTGRES_PASSWORD: qstack
    ports: ["5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]

  nats:
    image: nats:2.10
    command: ["-js", "-store_dir", "/data"]
    ports: ["4222:4222", "8222:8222"]
    volumes: ["natsdata:/data"]

  # Observability stack
  prometheus:
    image: prom/prometheus:latest
    ports: ["9090:9090"]
    volumes: ["./prometheus.yml:/etc/prometheus/prometheus.yml"]

  grafana:
    image: grafana/grafana:latest
    ports: ["3000:3000"]
    environment:
      GF_SECURITY_ADMIN_PASSWORD: admin

  loki:
    image: grafana/loki:2.9
    ports: ["3100:3100"]

  # Self-hosted Sentry / GlitchTip
  glitchtip:
    image: glitchtip/glitchtip:latest
    ports: ["8081:8000"]

volumes:
  pgdata:
  natsdata:

Запуск инфраструктуры

Bash
# Поднять только инфра (Postgres + NATS + Observability)
make infra-up

# Поднять всё (инфра + все сервисы)
make compose-up

# Остановить
make infra-down / make compose-down

Hot Reload

Каждый сервис может работать в режиме hot reload с использованием air:

Bash
# Установить air
go install github.com/cosmtrek/air@latest

# Запустить сервис с hot reload
cd services/compute
air

# Или через Makefile
make dev SERVICE=compute

air отслеживает изменения файлов и автоматически пересобирает + перезапускает сервис при каждом save. gRPC connections reconnect автоматически, NATS reconnect встроен.

Dashboard Hot Reload

Bash
cd dashboard
npm install
npm run dev  # Vite dev server с hot module replacement

Тестирование

Unit Tests

Bash
# Все тесты
make test

# Тесты конкретного сервиса
make test SERVICE=compute

# С покрытием
make test-coverage
# Генерирует coverage.html в coverage/
Go
// Example unit test
func TestCreateVM(t *testing.T) {
    ctx := context.Background()
    db := testdb.New(t)
    svc := NewComputeService(db, nil, nil)

    req := CreateVMRequest{
        TenantID: "test-tenant",
        ImageID:  "ubuntu-24.04",
        FlavourID: "standard-2",
    }

    vm, err := svc.CreateVM(ctx, &req)
    require.NoError(t, err)
    require.NotEmpty(t, vm.ID)
    require.Equal(t, "pending", vm.Status)
}

Integration Tests

Integration тесты запускаются в Docker Compose окружении:

Bash
# Запустить integration тесты (поднимает compose, тестирует, останавливает)
make integration-test

E2E Tests

E2E тесты запускаются в kind (Kubernetes in Docker) cluster:

Bash
# Поднять kind cluster
make kind-up

# Развернуть все сервисы
make kind-deploy

# Запустить E2E тесты
make kind-e2e

# Очистить
make kind-down

Linting

Bash
# Lint all services
make lint

# Lint specific service
make lint SERVICE=api

# Auto-fix
make lint-fix

Используется golangci-lint с набором линтеров: staticcheck, revive, gci, gofmt, goimports, gosimple, ineffassign, unused.

Debug Mode

Каждый сервис имеет debug mode, включаемый через QSTACK_DEBUG=true:

  • Verbose logging — каждый gRPC call, NATS message, DB query
  • pprof — /debug/pprof endpoint (CPU, mem, goroutine profiles)
  • Slow request logging — запросы > 1s логируются с stack trace
  • NATS debug — все published/subscribed messages логируются
