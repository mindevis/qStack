Развёртывание

qStack разворачивается в Kubernetes cluster для control plane. Агенты запускаются как native systemd сервисы на bare-metal хостах.

Pod Disruption Budget

YAML
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: qstack-api-pdb
spec:
  minAvailable: 2  # минимум 2 replicas во время eviction
  selector:
    matchLabels:
      app: qstack-api

Стратегия апдейтов

Rolling update per service

1. Deploy new replica alongside old (K8s rolling update) 2. Leader election: new pod wins lease, old steps down gracefully 3. Old pod drains (finish in-flight sagas, stop accepting new requests) 4. Old pod terminates (SIGTERM → graceful shutdown) Canary (Phase 13+): - Deploy v2 to 1 of 3 API pods → monitor error rate/latency → promote or roll back - Feature flags для risky changes (toggle без redeploy) Blue-green (для major schema changes): - v1 и v2 side by side, switch traffic at ingress level - Обе версии пишут в одну DB (backwards-compatible schema)

Graceful Shutdown

Все сервисы обрабатывают SIGTERM (K8s посылает SIGTERM перед kill):

  • API: стоп приёма новых запросов, finish in-flight (30s grace)
  • Compute: pause reconciler, finish current cycle, save state
  • Storage: finish in-flight volume operations
  • Agent: save local state cache, clean disconnect
  • Все: flush NATS publisher, close gRPC server, close DB connections

K8s terminationGracePeriodSeconds: 60 + PreStop hook (sleep 10s для drain load balancer).
