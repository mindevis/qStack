Contributing

Руководство для contributors qStack. Слайд по коду, коммитам, PR процессу и тестированию.

Стиль кода

Следуем Effective Go и Google Go Style Guide.

Форматирование

  • gofmt для форматирования — обязательно
  • goimports для сортировки импортов — обязательно
  • Pre-commit hook запускает lint + format автоматически

Структура пакетов

services/compute/internal/
services/compute/internal/
├── api/          # HTTP handlers (если есть REST endpoint)
├── grpc/         # gRPC service implementations
├── domain/       # Domain models, interfaces, business logic
├── repository/   # DB access layer
├── event/        # NATS event handlers
├── config/       # Service-specific config
└── handlers/     # Event handlers (NATS subscribers)

Package Organization

  • Domain logic → domain/ (не зависит от DB, gRPC, HTTP)
  • Repository pattern для DB access — domain объявляет interface, repository имплементирует
  • gRPC server → grpc/, имплементирует proto/ контракты
  • Event handlers → handlers/, подписки на NATS

Error Handling

  • Использовать pkg/errors для wrap'а: errors.Wrap(err, "context")
  • Domain errors → domain/ package с typed errors
  • gRPC errors → маппинг domain errors в gRPC status codes
  • HTTP errors → маппинг в HTTP status + JSON body
Go
var ErrVMNotFound = errors.New("vm not found")

func (r *vmRepo) Get(ctx context.Context, id string) (*VM, error) {
    vm := &VM{}
    if err := r.db.Where("id = ?", id).First(vm).Error; err != nil {
        if errors.Is(err, gorm.ErrRecordNotFound) {
            return nil, fmt.Errorf("get vm %s: %w", id, ErrVMNotFound)
        }
        return nil, fmt.Errorf("get vm %s: %w", id, err)
    }
    return vm, nil
}

PR Process

  1. Создать branch из main с правильным именем
  2. Реализовать изменения с тестами
  3. Запустить локально: make test, make lint
  4. Запустить CI: make kind-up && make kind-deploy && make kind-e2e && make kind-down
  5. Открыть Merge Request на GitHub
  6. Code Review — минимум 1 approval
  7. CI passes — build, test, lint, e2e
  8. Merge — squash merge into main

PR Checklist

  • ✅ Код соответствует gofmt/goimports
  • ✅ golangci-lint без warnings
  • ✅ Unit тесты покрывают новую логику
  • ✅ E2E тесты проходят (проверено локально)
  • ✅ Conventional commit messages
  • ✅ Breaking changes documented
  • ✅ DB migrations included (если есть)
  • ✅ Proto definitions updated (если есть gRPC изменения)

Mock Database

Unit тесты используют test database (SQLite) вместо PostgreSQL:

Go
func TestVMRepository(t *testing.T) {
    db := testdb.New(t)  // SQLite
    repo := repository.NewVMRepository(db)

    vm := &domain.VM{
        TenantID: "test-tenant",
        ImageID:  "ubuntu-24.04",
        FlavourID: "standard-2",
        Status:   domain.VMStatusPending,
    }

    err := repo.Create(context.Background(), vm)
    require.NoError(t, err)

    got, err := repo.Get(context.Background(), vm.ID)
    require.NoError(t, err)
    require.Equal(t, vm.TenantID, got.TenantID)
}

Code Review

Code review process включает минимум одного approver. Reviewers проверяют:

  • Архитектурную согласованность (соответствует ли plan.md)
  • Качество кода и именование
  • Test coverage
  • Security considerations (SQL injection, auth, validation)
  • Error handling coverage
  • Обратная совместимость (backwards-compatible API)
