Сервисы qStack

9 независимых микросервисов, каждый со своим go.mod, бинарником, схемой БД и развёртыванием.

API Gateway (qstack-api)

Gateway

qstack-api

Реплики
3+ (stateless, горизонтальное масштабирование)
DB Schema
— (stateless facade)
Ответственность
REST API Gateway, аутентификация (JWT), раздача Dashboard (Admin + User), валидация запросов, Saga orchestration для мульти-сервисных операций
gRPC клиенты
Подключается ко всем бэкенд-сервисам через gRPC с mTLS
Ключевые маршруты
/v1/vms/*, /v1/networks/*, /v1/storage/*, /v1/billing/*, /v1/ai/*, /admin/*, /user/*
Ключевые функции
Gin router, middleware (CORS, auth, logging, rate limiting), статическая раздача SPA, saga engine

Compute (qstack-compute)

Core

qstack-compute

Реплики
1 активный (leader) + 1 standby
DB Schema
compute_schema
Ответственность
Управление VMs, Hosts, Clusters, Reconciler (desired/actual state), Scheduler (распределение VM), Live Migration, High Availability
Leader Election
PostgreSQL advisory locks (ранние фазы) → etcd (Phase 3+)
DB таблицы
vms, clusters, hosts, vm_templates, events
K8s
StatefulSet (1+1), PDB

Reconciler Loop

Запускается каждые N секунд: 1) Читает desired_state из DB, 2) Запраживает actual_state у libvirt, 3) Сравнивает → применяет исправление при drift, 4) Обновляет actual_state, 5) Логирует событие

Storage (qstack-storage)

Core

qstack-storage

Реплики
1
DB Schema
storage_schema
Ответственность
Storage Pools, Volumes, Snapshots, Attach/Detach дисков к VM
Поддерживаемые бэкенды
libvirt pools, Ceph RBD, iSCSI, Local filesystem, S3
DB таблицы
storage_pools, storage_volumes, storage_snapshots
Принципы
On/Off (через конфиг), Swappable (смена бэкенда без кода), Async (операции не блокируют VM lifecycle)

Network (qstack-network)

Core

qstack-network

Реплики
1
DB Schema
network_schema
Ответственность
Networks, IPAM (IP Address Management), Subnets, DHCP, MAC адресация
Поддерживаемые бэкенды
libvirt networks, macvlan, VLAN
DB таблицы

Image (qstack-image)

Core

qstack-image

Реплики
1
DB Schema
image_schema
Ответственность
Image CRUD, Build/Convert задачи, кэширование на гипервизорах
Image Builder
ISO boot, cloud-init, kickstart/preseed, base image + overlay, snapshot VM disk → image
Image Converter
raw ↔ qcow2, vmdk ↔ qcow2, vhd ↔ qcow2

Billing (qstack-billing)

Billing

qstack-billing

Реплики
1
DB Schema
billing_schema
Ответственность
Tenants, Rate Plans, Usage Metering, Invoices, Quota Enforcement
Metering
Сбор метрик usage из агентов (NATS topic usage.collected): CPU, RAM, Disk, Network I/O, VM runtime, Snapshots
Платёжные шлюзы
Stripe, Manual/Internal, extensible (Yookassa, Crypto)
DB таблицы
tenants, rate_plans, usage_records, invoices, invoice_items, payments
Quota
Max VMs, Max CPUs, Max Memory, Max Disk, Max Public IPs, auto-suspend при просрочке

Backup (qstack-backup)

Safety

qstack-backup

Реплики
1
DB Schema
backup_schema
Ответственность
Планирование бэкапов, создание снапшотов, восстановление, верификация
Методы
Snapshot (live), Full Copy, Incremental (qcow2 chain), Block Replication (Ceph rbd-mirror), VM Export
Рекомендуемая стратегия
Hourly snapshots → Daily full copy → Weekly full export → rbd-mirror для DR
DB таблицы
backups
RTO/RPO
VM disk: RTO 10 min, RPO 15 min. Control plane: RTO 15 min, RPO 0 (sync replica)

AI (qstack-ai)

AI/ML

qstack-ai

Реплики
1
DB Schema
ai_schema
Ответственность
Advisor (рекомендации), Predictor (прогнозы), AutoHeal (ремедиация), Assistant (интерактивный чат)
AI Provider
OpenAI / Anthropic / Ollama / vLLM / custom (OpenAI-compatible endpoint)
Advisor
Превентивные рекомендации: over-provisioned VMs, cost optimization, capacity planning, anomaly detection
Predictor
Предиктивное масштабирование, предсказание сбоев (disk full, node overload), деградация производительности
AutoHeal
Предлагает remediation для common issues: restart VM, migrate, scale, clear disk
DB таблицы
ai_sessions, ai_advisories, ai_predictions, ai_token_usage
Принципы
On/Off, Provider-agnostic, Local capable (Ollama), Context-aware, Opinionated not autonomous (AI suggests, human confirms)

Agent (qstack-agent)

Edge

qstack-agent

Реплики
N (один на каждый гипервизор-хост)
DB Schema
— (local cache only)
Ответственность
Локальное управление libvirt, heartbeat, отчёт о ресурсах, миграция, автономная работа
State Sync
Периодический sync с control plane, кэширует desired state локально
Local API
gRPC endpoint для прямого управления без оркестратора
Health Check
Отчёт о здоровье хоста (CPU, memory, disk, libvirt status)
Resource Monitor
Трекинг resource usage, отчёт scheduler
Migration Handler
Обработка incoming/outgoing live migrations
Heartbeat
Периодический heartbeat к control plane (конфигурируемый интервал)
Autonomous: При отказе всех control plane сервисов существующие VM продолжают работать, агенты управляют local lifecycle.
